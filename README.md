# BetLab Live Parser App

Веб-приложение для отображения **реальных live-футбольных матчей** с сайта `https://betlab.club/live`.

## Что сделано

- Frontend на React показывает список live-матчей, счёт, минуту и основные показатели.
- Backend (`server/live-proxy.mjs`) делает реальный запрос к BetLab и возвращает данные через `/api/live`.
- Обновление данных на клиенте — каждые 30 секунд.
- Без платных API: используется бесплатный парсинг страницы-источника.

## Запуск

Откройте **2 терминала**:

```bash
# Терминал 1
npm run start:api

# Терминал 2
npm run dev
```

- API: `http://localhost:8787`
- Frontend: `http://localhost:5173`
- Проверка API: `http://localhost:8787/api/health`
- В dev-режиме Vite проксирует `/api/*` на API-сервер.

## Почему у вас было 502 в браузере

`502 Bad Gateway` на `http://localhost:5173/api/live` означает, что фронтенд достучался до локального API, но сам API **не смог получить данные с BetLab** (или не был запущен).

Что проверить:

1. Запущен ли backend: `npm run start:api`
2. Открывается ли health-check: `http://localhost:8787/api/health`
3. Что возвращает API: `http://localhost:8787/api/live`
4. Если в `details` указаны сетевые/403 ошибки — это блокировка со стороны источника/сети (нужен другой IP/VPS/прокси).
5. Для расширенной диагностики откройте JSON `debug` в ответе `/api/live` — там перечислены попытки поиска данных и API-эндпоинты, которые были проверены.

## Важно

1. Если сайт-источник изменит структуру HTML/JSON, парсер нужно будет обновить.
2. Если BetLab включает антибот-защиту на вашем хостинге (Cloudflare/WAF), сервер может возвращать `502`.
3. Для продакшена лучше запускать парсер на VPS с нормальным исходящим доступом.

## Переменные окружения

Frontend может использовать другой API URL:

```bash
VITE_LIVE_API_URL=https://your-domain.com/api/live
```

По умолчанию используется `/api/live`.
